# Security policy

LAITA Public remains a **single-operator, self-managed** application. Keep the reference HTTPS entry and API on loopback; a shared or remote entry requires an independently protected operator network boundary. The v0.3.0 code candidate has one Owner/Admin credential and **separate** local practice Teacher and Student passphrases, with server-enforced course memberships, role-scoped sessions and History. These are practice identities controlled by the operator, **not** independent enrolled students or real participant accounts. See [credentials and Canvas setup](docs/CANVAS.md).

Use only non-sensitive operator-owned input. Do not send student records, grades, submissions, credentials, private institutional material or sensitive research data. Safety filters are bounded heuristics, not a certification.

OpenAI is optional and explicit. On the macOS reference deployment, keys stay in the operator's Keychain and are consumed through a server-only one-use handle. Configuration contains opaque references and synthetic naming examples only. Do not put API keys in `.env`, JSON, Git, browser storage, SQLite, logs or screenshots.

Text, transcripts, answers, provenance, feedback and diagnostic state persist locally with no automatic expiry. Raw audio is temporary. New conversation resets context but does not delete history. Use disk/account protection; built-in encryption at rest is not provided. Local Admin and practice passphrases are stored only as separate salted scrypt verifiers in the existing SQLite, with no built-in usable default password.

Report vulnerabilities privately using GitHub's private vulnerability reporting when available on this repository. If unavailable, contact the maintainer using the contact route on the [public faculty profile](https://www.jmu.edu/cise/people/faculty/wei-xuebin.shtml), first sending only a high-level description and asking for a secure reporting channel. Do not post exploit secrets or private data in public Issues. No response-time guarantee is made.

See [validation and limitations](docs/VALIDATION.md) for the exact Public source/release validation scope. The public repository has CodeQL default setup, hosted secret scanning and push protection enabled. These checks are not a security certification or deployment acceptance. No paid security service is required.

The optional course-level **LTI 1.1** flow verifies an OAuth HMAC-SHA1 launch against the operator-configured exact Canvas HTTPS origin/course/identity/role, a bounded timestamp and a SQLite-backed one-time nonce. Only a signed, authorized **Instructor** can reach Teacher tools; an authorized **Learner** is mapped to the limited Student role and never to Admin. A disabled/revoked local account, missing course grant, expired session, or changed configuration fails closed. The LTI shared secret lives only in a protected owner-only file. Role sessions use HttpOnly/Secure/SameSite cookies, same-origin mutation protection and bounded lifetimes. The legacy server-control credential is independent of these browser roles.

Canvas REST access uses a **separate** operator-owned time-limited Teacher token for the exact authorized course, not LTI launch secrets. Teacher writes are limited to supported unpublished Page/Assignment/Module creation, title-only edits on approved assignments, approved Module item appends, and specifically reviewed Test Student feedback comments—never automatic grading or publication. The Teacher chooses destinations, must approve the actual preview, and receives bounded readback; unknown results are not blindly retried. Optional GitHub/MongoDB practice verification remains read-only against approved targets. No real institutional student-data access or deployment is established by the public fixtures.

Media containing captured application screens is subjected to a narrow, exact-path public-sanitization allowlist. New Owner-supplied DEV demonstration GIFs and screenshots in the Draft documentation branch are **not** an exception to that gate; their precise paths need a separately reviewed approval and final privacy/provenance check before publication. Never disable this check merely to make CI pass.
